## P0: what a judge sees in the first minute

### P0-1. A visitor with no wallet gets developer messages
Observed: on a fresh browser, `#/overview`, `#/recover`, `#/rules` and `#/incidents` show "Agent offline and no saved
config. Start it from the repo root with `pnpm agent`; this page reads `GET /config`…". `#/recover` shows nothing else.
Fix:
- [x] `lib/nav.ts`: a hosted browser with no wallet (`hasSeed === false`) gets only the Start group.
- [x] `App.tsx`: in the hosted build with no wallet, every screen but Start renders a `NoWallet` empty state
      ("No wallet in this browser yet" + "Get protected"); `Banners` is not shown.
- [x] Hosted build banners never mention `pnpm agent` or `GET /config`: "Your Guardian is not answering right now.
      Chain reads below are live." (also the Rules "Agent offline: editing is off" banner).
- [x] Tests: `nav.test.ts` (visitor groups), a pure banner/status helper test.

### P0-2. "Guardian offline" for someone who has no Guardian
Observed: the sidebar shows a grey "Guardian offline" to a fresh visitor, which reads as an outage.
Fix:
- [x] Move the status logic to a pure `guardianStatus()` (tested): visitor → "Not set up yet"; wallet but no Guardian
      config yet → "Setup not finished"; otherwise as today.

### P0-3. "Lock wallet" while the wallet is locked
Observed: the sidebar shows "Lock wallet" whenever a wallet is stored, while the page says "Your wallet is locked".
Fix:
- [x] `lib/session.ts`: `onChange(listener)` fired on create, unlock, providePqc and lock (tested).
- [x] Sidebar: "Lock wallet" only while unlocked; "Wallet locked" otherwise. Unlocking on any page updates it.

### P0-4. Alert settings that tell a browser user to edit `.env`
Observed: Rules → "Alert channels … set in the agent's `.env` (`TELEGRAM_BOT_TOKEN`…)". Overview → "Alerts: None set".
Fix:
- [x] Hosted owner: the card says alerts are not available on the public instance yet and that rescues show on
      Overview and Incidents. Overview's row reads "Not available yet". Local mode keeps today's text.

### P0-5. The threshold is labelled QOR but counts tokens
Observed: Rules → "Threshold (QOR) … Now: 1,000 QOR"; Overview → "Transfers above 1,000 …". `rules.ts` compares
`tx.amount` (a token amount, 18 decimals) with `maxOutbound`.
Fix:
- [x] Copy: "Largest transfer to a trusted address (any token)", "Now: 1,000 fUSD, fETH or fBTC per transfer", the save
      message and Overview's line likewise.

### P0-6. The signed report's template summary shows wei and full addresses
Observed: "Outbound transfer of 100000000000000000000 (token 0x8478…a14) to 0x255F…75E7 in tx 0xcca2…" on Incidents.
Fix:
- [x] `templateSummary` takes token labels (address → symbol, 18 decimals) from the agent config: "10 fUSD sent to
      0x255F…75E7 (tx 0xcca2…2704), which is not a trusted address. The Guardian moved 3 of 3 token balances into
      your vault." Unknown tokens keep the raw amount and address. Tests in `report.test.ts`.
- [x] Old incidents keep their signed text (the summary is inside the signature).

## P1: product gaps (after P0, by priority)
1. Recover with the recovery code only, on a new device: the vault accepts a withdrawal signed by the ML-DSA-87 key
   from any submitter, but the UI needs the browser-stored seed. Highest value, touches the core promise.
2. Account page: address + copy/QR, balances, change password, remove the wallet from this browser, turn off
   protection / retire the Guardian (`TurnOff` is hidden for hosted owners).
3. Alerts for hosted owners (email, Telegram link or web push).
4. Plain-language layer: tooltips for EVM window, ML-DSA-87, ECDSA, `vault.rescue`, uqor; technical rows folded
   under "Technical details".
5. Onboarding in three user-facing steps (wallet + code, starter QOR, "Turn on protection" running the rest).
6. Landing: how-it-works visual, FAQ (risk, cost), GitHub / threat model / audit links, a clear testnet label.
7. Small: hide Overview's intro card and the "Get protected" nav item once protected; shorter activity rows.

Whatever P1 does not ship by the freeze goes into README "Known limitations".
