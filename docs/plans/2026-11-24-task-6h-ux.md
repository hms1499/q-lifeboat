# Task 6H: UX clarity pass (sub-plan)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan.
> Low tier (dashboard UI only): Implement → Verify → Ship, no per-task independent review (CLAUDE.md risk tiers).

**Goal:** a first-time viewer understands what Q-Lifeboat does within 10 seconds of opening the dashboard, sees only
their own incidents, gets a clear message when diana is slow, and reads incidents in plain words.

**Architecture:** dashboard-only changes (apps/dashboard). Pure helpers in `src/lib/` with vitest tests (node env),
wired into the existing screens. No agent, CLI, core or contract change: the agent's signed `summary` is kept and shown
as the agent's text; the plain-words headline is computed in the browser from the signed structured fields.

**Tech Stack:** Vite + React + TypeScript, vitest, viem (`publicClient` in `src/lib/chain.ts`).

**Source:** UX review of 2026-11-24 (builder approved findings P0 1-4 and P1 6-7 as Task 6H).

## Global Constraints

- Repo files, comments and commits in English. No personal paths in committed files.
- Chain reads go through the existing helpers (`publicClient`, `restBase()` proxy; chain fact 18). EVM tx hashes are
  copyable text, never explorer links (chain fact 19).
- Never show an incident as belonging to the owner, or as safe, from the agent's word alone: ownership comes from the
  chain (the trigger tx's sender), the ✓/✗ verification is unchanged.
- Existing tests stay green: `pnpm -F dashboard test`, `pnpm -F dashboard build` (after `cd contracts && forge build`).

## Review Focus

1. An incident whose trigger sender cannot be read yet (diana slow) is not hidden and not mislabelled: it stays in the
   main list marked "checking owner", never silently dropped.
2. The plain-words headline never contradicts the verification: it describes what the signed report claims ("The
   Guardian reports …") and the ✓/✗ badge stays the authority.
3. The slow-chain message appears only while there is no data yet and goes away when data arrives; a later failed read
   keeps the last good value (existing `usePoll` behaviour).
4. The explainer is short enough to read in 10 s and can be dismissed; dismissal persists in `localStorage` (wrapped in
   try/catch) and a "How it works" link brings it back.

### Task 1: Helpers (TDD)

**Files:** create `apps/dashboard/src/lib/explain.ts` + `explain.test.ts`; modify `src/lib/hooks.ts`,
`src/lib/incidents.ts` (+ `incidents.test.ts`), `src/lib/chain.ts` if the receipt type needs `from`.

**Interfaces (produced):**
- `describeIncident(i: Incident, cfg: AgentConfig | null): { headline: string; detail: string }` — plain words from the
  signed fields, token symbols via `tokenSymbol`, amounts via `fmtAmount`, addresses via `shortAddr`. Examples (exact):
  - transfer + rescues: headline `"10 fUSD left your account to 0xe256…59f3, which you don't trust"`, detail
    `"The Guardian reports it moved 90 fUSD into your vault."` (sum successful rescue `amount` per token, joined with
    `" + "`, e.g. `"97 fETH + 100 fBTC"`; when nothing moved: `"The Guardian reports it tried a rescue but nothing moved."`).
  - approval: headline `"Your account approved 0x5555…5555 to spend unlimited fUSD"` (unlimited when amount is
    maxUint256, else the amount), same detail rule; an alert with no rescues: detail
    `"No rescue: the rules flag this for you, but moving funds would not undo it."`.
  - native QOR (token = zero address): symbol `QOR`.
- `partitionByOwner(list: Incident[], senders: Record<string, string | null | undefined>, owner: string):
  { mine: Incident[]; others: Incident[]; checking: Incident[] }` — `senders[trigger.hash.toLowerCase()]`:
  a string equal to `owner` (case-insensitive) → mine; another string → others; `null`/missing → checking.
  Order preserved (input is already sorted).
- `useTriggerSenders(list: Incident[]): Record<string, string | null>` (hook in `hooks.ts` or `incidents.ts`) — reads
  each trigger tx's sender once (receipt or transaction `from`) and caches it; a failed read leaves it missing (retried
  on the next list change or after 15 s).
- `Polled<T>` gains `slow: boolean`: true when `data === undefined` and the first attempt for the current key started
  more than `SLOW_MS = 8_000` ms ago. Pure helper `isSlow(startedAt: number | null, now: number, hasData: boolean): boolean`.
