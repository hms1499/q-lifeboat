# Homepage Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A full-width homepage for visitors to the hosted dashboard, built from approved mockup A.

**Architecture:** A new `Home` screen in `apps/dashboard`, rendered outside the sidebar shell. `App` sends `#/` to it
for a browser with no wallet, and `#/home` always. Static proof data and links live in `lib/home.ts`.

**Tech Stack:** React 18 + Vite, vitest, the dashboard's `styles.css` tokens.

**Spec:** `docs/superpowers/specs/2026-11-26-homepage-design.md`

## Global Constraints
- Copy and section order as in mockup A (`.superpowers/brainstorm/86704-1795662054/content/homepage-v1.html`).
- Every number on the page comes from `docs/EVIDENCE.md` (Task 12 section) or `/api/status`. No explorer links for EVM hashes.
- No `href="#section"` anchors: the app routes on `#/…`.
- Repo files, comments and commits in English. Risk tier: Low.

## Review Focus
- `/api/status` unreachable or paused: the hero still renders; the CTA shows `landingStart`'s reason, the live count is hidden.
- A browser WITH a wallet opening `#/`: lands on Overview as today, not on Home.
- `#/start` while onboarding is open: no second "Get started" card.
- 390 px width: no horizontal scroll (the diagram and the proof table scroll inside their own boxes).
- Keyboard: the FAQ `<details>` and the scroll buttons are reachable and focus-visible.
